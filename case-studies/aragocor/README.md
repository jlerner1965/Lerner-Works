The case study deliberately runs three images, not seven — it's a long read,
and the brief was that it should read rather than scroll.

## How these were taken

The previous set had three faults, all of them visible on the page: the
browser scrollbar ran down the right edge of every capture, the corners
carried window rounding, and two of the three were cut mid-section —
`04-products.jpg` sliced through the product cards, which was the worst of
them, because its caption pointed at the particle sizing that the slice cut
off.

The fix was to stop taking viewport slices. Each capture is now framed on a
real boundary: the hero as a visitor meets it, and each grid band whole, from
its eyebrow down past the last card. Clipping to `clientWidth` rather than the
window width is what keeps the scrollbar out of frame.

1600 px matches the lead-image convention the rest of the site uses; the body
figures are 1200 px, which is where they stop being worth the bytes. That is
about 1.6× the largest size either is displayed at — sharper than the 1265 px
originals, short of a true 2×, and a deliberate stop rather than an oversight.

Chromium in the build environment does not trust the agent proxy's CA, and
disabling TLS verification to get a screenshot is not a trade worth making.
Node does trust it, so the capture script routes every request the page makes
through a Node `fetch` and fulfils it into the browser: Node does the TLS,
Chromium only ever sees bytes that were already verified.

## Replacing any of these

Drop the new file in, keep the filename, then from the repo root:

```sh
python3 -m http.server 8765 &
node tools/optimize-images.js            # regenerates 01-home-hero-thumb.jpg
python3 tools/set-image-dims.py --write  # writes real dimensions into the HTML and og:image
node tools/measure.js                    # update the table on /work/lernerworks/ if the weight moved
```

`set-image-dims.py` is the one that matters most: the CSS sets `height:auto`,
so a mismatch never distorts an image, but those attributes are what reserve
the right space before the file loads and keep the page from shifting.

**Check the capture before committing it.** The faults above were all visible
in the file itself and shipped anyway. Look for: a scrollbar at the right
edge, rounded corners, and anything cut through the middle of a card, a row or
a heading. A cut at a section boundary looks deliberate; a cut mid-card looks
like a mistake, because it is one.

Four further captures — `02-home-process`, `05-industries`, `06-sustainability`
and `07-science` — were removed rather than re-taken. Nothing referenced them,
they carried the same three faults, and the site has changed since: the
applications grid had six cards when they were taken and has eleven now. They
are in the git history if a fourth figure is ever wanted.

No stock photography here — these are screenshots of real work only.
